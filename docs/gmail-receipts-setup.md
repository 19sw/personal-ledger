# Gmail 邮件账单设置与核对

这份指南说明如何先检查 Gmail 识别规则，再决定是否开启自动记账。所有账号登录、授权、上传和发布都由你本人操作；每次推送或发布前，PM 会先征得你的同意。

## 会记哪些邮件

- DoorDash 外卖：记为“餐饮”。DoorDash 的订单确认邮件写的是预估总额（estimated total，下单后小费还能改），这类邮件照常记账，但账目标为“待核对金额”：如果你改过小费，点开改成实际扣款；没改过就确认。G1 日志里这类邮件显示为 `receipt(ESTIMATED_TOTAL_REVIEW)`（2026-10-26 决定）。
- Uber Eats 外卖：记为“餐饮”。
- Uber 打车：记为“交通”，商家显示“Uber”。支持英文总额标签和中文“总计”，包括 `US$` 金额；上传修复后仍要用 G1 对照原邮件核对。
- 其他像收据的邮件不会自动入账，会出现在“我的 → 待查看邮件”。你可以自己决定怎么处理。

### 如何区分收据和广告

姓名只作辅助线索，不会因为出现姓名和金额就自动记账；收据没有姓名也可以识别。程序不保存姓名，也没有姓名设置。

- 只有收据、已付款、订单确认或已完成行程等消费证据，并且读到唯一可信的美元总额，才会自动新增账目；标明待付款的订单不自动入账。
- 支持 `Total`、`Grand Total`、`Amount Paid`、`总计`、`实付`，以及已有平台总额标签。金额可以与标签同一行或紧接下一行；不承诺识别所有语言或邮件排版。
- 小计、车费分项、优惠和满减门槛不当作最终总额；促销页脚不会单独否定一封有明确消费证据的收据。
- 新收据缺少金额、出现冲突金额、币种不是美元，或消费证据不足时，进入 **我的 → 待查看邮件**，不新增猜测金额的账目。明确广告忽略。退款和既有订单的金额修订仍按原流程处理。
- 商家名单仅决定哪些商家允许自动记账，不能跳过这些判断；名单外邮件仍需你确认。

程序只读 Gmail，不会发送或删除邮件。搜索范围比以前更广：除了内置商家和你加入名单的商家，还会检查最近 3 天中 Gmail 归类为“购物”或主题像收据的邮件。名单外邮件不会自动记账。Google 授予的是 Gmail 只读权限；“只找这些邮件”是程序的筛选规则，不是 Google 权限本身的限制。

## 1. 上传后重新运行 setupLedger

等 PM 取得你的同意并完成代码推送后：

1. 打开账本对应的 Apps Script 项目。
2. 在函数菜单中选择 `setupLedger`，点击“运行”。这次需要重新运行，因为程序增加了商家名单表。
3. 安全地重复运行不会清空已有账目、类别和设置；它会按需创建缺少的表格和列，包括 `gmail_pending`（待查看邮件）和 `mail_senders`（商家名单）。
4. 如果出现授权页面，确认 Gmail 权限仍是只读。如果页面要求发送、删除或管理邮件，请取消并告诉 PM。

运行完后，网页应能照常打开。即使尚未运行新版 `setupLedger`，网页也不应因此无法载入；但要开始邮件处理，必须先完成这一步。

## 2. 先做只读试运行 G1

G1 不写账本、不改商家名单，也不会开启自动轮询。第一次运行 Gmail 函数时可能需要你授权只读访问。

在 Apps Script 的函数菜单中选择 **`dryRunReceipts`**，点击“运行”。菜单里选择的是函数名，不需要填写括号或参数。它会依次查看 DoorDash、Uber 和 Uber Eats 的候选邮件。

如果需要只检查一个商家，或检查名单外邮件，可请 PM 指导添加临时函数来调用 `dryRunReceipts('doordash')`、`dryRunReceipts('uber')`、`dryRunReceipts('ubereats')` 或 `dryRunReceipts('broad')`；这些带参数的表达式不能直接在函数下拉菜单中选择。

内置商家每组查看最近最多 10 封候选邮件；`broad` 检查名单外的收据候选邮件。日志只显示邮件编号最后 6 位、日期、发件网域、识别到的金额或错误代码、邮件类型／原因及金额标签；不显示邮件主题、正文或片段。试运行只读，不写入账本或商家名单。

Uber 和 Uber Eats 都使用 `uber.com` 发信，因此两组试运行可能显示相同的邮件编号。这表示搜索候选重叠，不代表重复入账，也不能当作两组都已验证通过。程序根据邮件头识别平台；打车显示“行程总额标签”，外卖显示“总额标签”。真正轮询时会合并搜索，并按完整邮件编号去重。

请核对：

- `receipt` 表示收据，`other` 表示其他邮件；这列不是账目类别。餐饮／交通要在 G2 入账后核对：DoorDash 和 Uber Eats 为“餐饮”，Uber 行程为“交通”。即使打车邮件正文或页脚提到 Uber Eats，也不能把它当成外卖。
- Uber One、Uber Cash 和促销不应记账。
- 金额应是实际支付总额，不是商品小计或行程车费。中文收据应显示“总计”标签；如显示 `TOTAL_NOT_FOUND`（没找到总额）、`MULTIPLE_TOTALS`（多个不同总额）或 `CURRENCY_UNKNOWN`（非美元），这一项还未通过，先告诉 PM，不开启轮询。
- broad 试运行中的名单外邮件应标为待查看候选，不应自动入账。静音商家的邮件应被跳过。
- 对 DoorDash：没有订单号时，只有同一家餐厅在 6 小时内的邮件才提示可能重复；读不到餐厅名时不提示。

如果结果不对，只把商家类别、日志中的编号后 6 位、日期、错误代码和金额标签告诉 PM。不要转发邮件、复制真实邮件内容或发截图。

## 3. 在“待查看邮件”里处理邮件

打开记账网页，进入 **我的 → 待查看邮件**。每封会显示发件网域、日期、识别金额；读不到金额时显示“未读到金额”。也可以点“在 Gmail 中打开”查看原邮件。程序不会把原文保存到账本。

四个操作的效果：

- **记这一笔**：打开现有记账面板，预填识别到的商家和金额。你选择类别并保存后，邮件会标记为已处理。同一封邮件再次扫描不会再新增一笔。
- **以后自动记**：先选择类别。程序把这个发件网域加入自动名单，并把当前这封邮件记入账本。以后只有具备消费证据、且能识别出唯一实付总额的邮件才会自动入账；不符合时仍会进入待查看。
- **不再提醒这个商家**：静音这个发件网域，并隐藏该网域所有待查看邮件。它不会因此创建账目。
- **已查看**：只关闭当前这封，不会加入自动名单，也不会记账。

名单外的邮件在最近 3 天搜索范围内处理。不会回头读取更早的旧邮件补账。

## 4. 加入、静音、移除或恢复商家

通常用待查看邮件中的按钮管理商家即可。第一版没有单独的商家设置界面；必要时可以在账本的 `mail_senders` 表中调整：

| 列 | 用途 |
| --- | --- |
| `domain` | 发件人网域，只保存 `@` 后面的网域，不保存完整邮箱地址 |
| `display_name` | 账目中显示的商家名称 |
| `category_id` | 自动记账使用的类别 |
| `mode` | `auto` 自动记账，或 `muted` 静音 |
| `created_at` | 添加时间 |

- **静音商家**：将对应行的 `mode` 设为 `muted`。这个商家的待查看邮件会隐藏，程序在读取正文前会跳过它。
- **恢复提醒**：删除该网域的静音行。之后它若再次符合收据候选条件，会重新进入待查看；你也可以在那里选择“以后自动记”。
- **移除自动名单**：删除对应的 `auto` 行。以后该商家的收据不会再自动入账；符合扫描条件时会进入待查看。

只修改表格中的数据行，不要改列名或列的顺序。若不确定该编辑哪一行，先告诉 PM。

## 5. G1 核对通过后再开启 G2

只有你核对 G1 并同意继续后，才运行 `enableReceiptPolling`。它会安装每 5 分钟运行一次的轮询。再次运行不会重复创建定时器。

开启后，每轮最多处理设定数量的邮件；超出部分会留给下一轮，不会一次性无限读取。处理范围是最近 3 天，已处理邮件会去重。G1 通过不等于真实收据已验证；用下一次真实外卖或打车检查类别、商家、总额和邮件到入账的时间。

G1 可以检查很早以前的收据，G2 不会因为 G1 看过它就补记旧账。核对一笔最近收据入账后，等待下一轮，确认没有新增第二笔。此前已经处理成“待补全”的账目不会在修复后自动重新读取，请在网页里补填；已进入“待查看邮件”的也需在该列表处理；不要删除去重凭据来重试。

如果之后想暂停，在 Apps Script 中运行 `disableReceiptPolling`。这只会停止自动轮询，不会删除已有账目或邮件标记。

## 安全提醒

- 不要把真实邮件、截图、脚本或表格标识、部署信息、口令发到聊天或放进仓库。
- 账本只保存发件网域和识别金额等处理所需信息；不保存完整发件地址、主题、正文或片段。
- 自动名单只对你加入的网域生效。名单外邮件不会自动入账。
- 推送、开启轮询和发布都要先得到你的同意。
