# 准备工作：创建 Google 表格与谷歌脚本项目（给你本人操作）

> 这份说明请你**自己一步步操作**：所有登录都由你本人完成，开发代理不会登录你的任何账号。
> 文中**不包含**任何网址、脚本 ID、口令。操作过程中出现的 ID、网址，请不要发到聊天里，也不要放进代码仓库或截图。
> 标 **【未核实】** 的步骤，是我们还没能实际确认的地方；如果你看到的界面不一样，停下来告诉 PM 即可。

这次只做“准备”：建表格、建项目、在电脑上登录 clasp（把代码传到 Google 的工具）、把脚本 ID 填进本机文件。
**暂时不要运行 `clasp push`，也不要部署**，这两步下一阶段会再跟你确认。

---

## 第 1 步：确认使用的 Google 账号，并开启两步验证

1. 使用你平常用的那个 Gmail 账号。DoorDash、Uber Eats 和 Uber 打车的收据都要发到这个账号。名单外像收据的邮件只会进“待查看邮件”，不会自动记账。
2. 打开 Google 账号设置，进入 **安全**（Security）→ **两步验证**（2-Step Verification）。
3. 如果显示“已开启”，这一步完成；如果没有开启，按提示开启（通常需要手机号或手机上的 Google 提示）。

> 为什么：记账数据和 Gmail 读取权限都在这个账号下，两步验证能防止别人只凭密码登录。

## 第 2 步：创建「账本」表格

1. 在电脑浏览器中登录上面的账号，打开 **Google 表格**（Google Sheets），新建一个**空白**表格。
2. 把表格名称改为 **账本**。
3. 里面暂时什么都不用填。以后程序会自动建好工作表（`entries`、`categories` 等）。

> 以后可以随时打开「账本」查看数据，但**请不要手动修改、排序或删除其中的行和列**，否则程序可能读错。需要改账目时，请在记账网页里改。

## 第 3 步：创建项目 M（记账主程序），绑定在「账本」上

1. 在「账本」表格中，点菜单 **扩展程序** → **Apps Script**。会打开一个新的脚本编辑器页面。
2. 点左上角的项目名称（默认是“无标题项目”），改名为 **记账-主程序**。
3. 编辑器里自带一个空的 `Code.gs` 文件，可以不管它（以后传代码时会被替换）。
4. 点左侧的齿轮图标 **项目设置**，找到 **脚本 ID**，先不用复制，第 6 步再用。

## 第 4 步：创建「收件箱」表格和项目 I（Apple Pay 收件口），绑定在「收件箱」上

1. 再新建一个空白 Google 表格，命名为 **收件箱**。
2. 在「收件箱」中点 **扩展程序** → **Apps Script**，把项目改名为 **记账-收件口**。
3. 这个项目的代码会在后面的切片（Apple Pay）里完成，现在保持空白即可。

> 「收件箱」表格**永远不要手动排序、编辑或删除行**：收件口靠最后几行的时间来防止被刷（spec 5.3），手动改动会让限流失效或误判。

## 第 5 步：开启“Google Apps Script API”（clasp 需要）

1. 打开 Apps Script 首页（就是你刚才看到的脚本编辑器所在网站），点左侧 **设置**（齿轮图标）。
2. 找到 **Google Apps Script API**，把开关打开。

> 【未核实】我们没有在你的账号里确认 clasp 3.x 是否一定要求打开这个开关；按照常见做法先打开。它只允许“你自己用 clasp 管理你自己的脚本”，不会产生费用。如果找不到这个开关，告诉 PM。

## 第 6 步：在电脑上登录 clasp（由你本人操作）

clasp 已经作为开发工具装在项目里（`node_modules`），不需要全局安装。

1. 打开 Mac 的“终端”（Terminal）。
2. 进入项目文件夹（把下面的路径换成你电脑上项目文件夹的位置）：
   ```bash
   cd 你的项目文件夹路径
   ```
3. 运行：
   ```bash
   npx clasp login
   ```
4. 浏览器会打开 Google 登录与授权页面。确认是**第 1 步的那个账号**，按提示允许。
5. 看到登录成功的提示后回到终端。

> 登录凭据保存在你电脑的用户目录（文件名 `.clasprc.json`），**不在项目文件夹里**，不会被提交。项目的 `.gitignore` 也已把它列为忽略，以防万一。
> 不要把这个文件发给任何人。不用时可以运行 `npx clasp logout` 退出。

## 第 7 步：把项目 M 的脚本 ID 填到本机文件（不提交）

1. 在项目 M（记账-主程序）的 **项目设置** 中复制 **脚本 ID**。
2. 在项目文件夹里，把 `apps/main/.clasp.json.example` **复制**一份，命名为 `apps/main/.clasp.json`。
3. 用文本编辑器打开 `apps/main/.clasp.json`，把 `"scriptId"` 后面引号里的中文说明替换成你复制的脚本 ID，保存。`"rootDir": "."` 保持不变。
4. 检查它不会被提交：在终端运行
   ```bash
   git status --short
   ```
   列表里**不应出现** `apps/main/.clasp.json`（只会看到 `.clasp.json.example`，它本来就在仓库里）。如果出现了，先停下来告诉 PM。
5. 可以运行下面的命令，看看哪些文件将来会被上传（这个命令只在本机检查，不会上传）：
   ```bash
   cd apps/main
   npx clasp show-file-status
   ```

项目 I（收件口）的脚本 ID 在开启 Apple Pay 自动记账时再填，步骤见 `docs/applepay-setup.md`（使用 `apps/inbox/.clasp.json.example`）。

## 以后的步骤（现在先不要做，届时会再确认）

下面只是让你知道接下来会发生什么：

1. 在 `apps/main` 目录内运行 `npx clasp push`：把代码传到项目 M。（不要用 `npx clasp -P apps/main push`，clasp 3.4.1 会报 “srcDir escapes project root”。）
2. 在脚本编辑器中运行一次 `setupLedger`：在「账本」里建好工作表和默认类别。第一次运行时 Google 会请你授权（会出现“未验证应用”提示，需要点“高级 → 继续”，这是 spec 6.1 已说明的正常情况）。授权页面**这时就会列出“查看你的电子邮件”（Gmail 只读）**，以及读写表格、管理定时器的权限。虽然读 Gmail 的功能要到外卖收据切片才会用到，但权限清单一次写全，这是预期的、你已批准的（§11 第 4、5 项）；程序没有发信或删信的权限。
3. 部署为网页应用：访问权限选 **只有我自己**，以 **我** 的身份运行。把网址添加到 iPhone 主屏幕。
4. 运行一次 `installTriggers`：安装“每日清理”定时器（删除超过 30 天的“最近删除”账目）。
5. 按 `docs/checklist-slice1.md` 在手机上逐项检查。

## 以后更新代码后：重新运行一次 setupLedger（补新类别、建预算表、打卡和小助手）

**打开网页不会改动你的账本结构**，所以每次在你批准并推送新代码（`clasp push`）之后，请在脚本编辑器里再运行一次 `setupLedger`。（2026-10-15 第二版推送后你已运行过一次，表格已建好。第三版只改了程序，不需要再运行。以后如果某次更新需要，PM 会提前告诉你。）重新运行会：

- 补上「账本」里还没有的默认类别（蔬菜、水果、零食……奖金、红包礼金等）；你已有的类别、账目、同名类别（包括已删除的）都不会被改名、重新启用或重复添加；「其他」「未分类」会被排到各自列表的最后。
- 新建两张工作表 `budgets`（预算历史）和 `settings`（设置，写入“预算提醒比例 = 80”）。已有的工作表和数据一行都不会改；已经存在的设置值不会被覆盖。
- 新建三张工作表 `checkins`（打卡日期）、`assistant_messages`（小助手的提醒和夸奖）、`assistant_state`（小助手的规则状态，用来防止重复提醒）。
- **按已有账目的创建时间补上打卡**（费城日期，每天一行；已删除但还在 30 天内的账目也算）。已经有的打卡行不会被改动。补完后第一次打开网页，小助手只会发一条“已达到的最高里程碑”的祝贺，不会把 1、3、7 天……逐条补发。
- 邮件收据切片（Task 12）：新建 `gmail_pending`（保存邮件编号、发件网域和识别金额，不保存主题或正文）、`mail_senders`（商家名单），并给 `channel_status` 补一列 `last_latency_sec`。这一步**不会**开始读邮件；如何试运行、查看待处理邮件及开启和停止，见 `docs/gmail-receipts-setup.md`。
- 重复运行是安全的：没有新内容时什么都不会改变。

在重新运行之前：网页照常可以记账、看报表和账单；预算页会提示“请先重新运行一次 setupLedger”，此时不能设置预算或修改提醒比例（网页不会自己建表）。“我的”页的打卡卡片和小猫助手窗口也会提示先运行 setupLedger；小助手的 5 个问题按钮照常可用，但不会产生提醒，也不会出现红点。这期间新记的账，在重新运行时会按创建时间补上打卡。

重新运行之后：每天的清理任务（`dailyCleanup`，已安装的定时器不用重装）还会删除 90 天前的小助手消息；打卡记录永远保留，删除或清除账目都不会减少打卡天数。

## 安全提醒（请一直遵守）

- 不要把脚本 ID、表格网址、网页应用网址、收件口口令发到聊天、截图或代码仓库。
- **永远不要用 iCloud 链接分享 Apple Pay 快捷指令**，也不要截图其中“获取 URL 内容”的步骤：里面会有收件口网址和口令（Apple Pay 切片时才会创建）。
- 不要手动排序或编辑「收件箱」；「账本」只看不改。
- 演示视频请使用测试数据，镜头避开地址栏和脚本属性页面。
