# 个人记账应用：第一版产品需求

本文件把已批准的范围展开成具体页面和行为，2026-10-12 经用户审阅确认。本文件只讲“应用怎么用”，不选定技术、服务商或授权方式。

## 1. 页面一览

| 页面 | 作用 |
| --- | --- |
| 登录 | 保护云端账本，只有你能看到账目。具体登录方式在技术方案中确定 |
| 账目（首页） | 按月查看交易；顶部提示待补全、待核对的数量 |
| 记一笔／编辑 | 手动录入收入或支出，修改任何一笔记录 |
| 月报 | 支出报表、收入报表、收支对比三部分 |
| 设置 | 管理类别、兼职来源与预算；查看两个自动入口的运行状态 |
| 小助手（全局） | 每个页面左上角的小图标，点开为对话窗口（见第 6A 节） |

手机竖屏为主要使用场景，底部导航切换“账目／记一笔／月报／设置”。

## 2. 一笔交易包含什么

| 字段 | 说明 |
| --- | --- |
| 类型 | 支出或收入 |
| 金额 | 美元，保留两位小数；可以为空（待补全） |
| 日期时间 | 交易发生时间；按费城所在时区决定属于哪个月 |
| 类别 | 见下方默认清单；可在设置页增删 |
| 具体来源 | 仅收入使用，例如“兼职 A”；可从已有来源中选择或新增 |
| 商家／说明 | 自动记录时填入识别到的商家，例如 DoorDash |
| 备注 | 自由填写 |
| 记录渠道 | 手动、Apple Pay、Gmail（DoorDash、Uber Eats、Uber 打车及用户加入名单的商家）；自动生成，不可修改 |
| 退款标记 | 退款记录为一笔负支出，并关联原交易 |
| 状态 | 正常、待补全、待核对重复、待核对金额 |

**默认类别（2026-10-12 已确认）：**

- 支出：餐饮、购物、交通、住房、日用、娱乐、其他、未分类
- 收入：工资、兼职、其他

自动记录还会保存用于去重和核对的凭据（例如邮件编号、订单号），但不保存完整邮件正文。

## 3. 账目页（首页）

- 默认显示本月，可左右切换月份。列表按日期倒序分组，每天显示当日支出小计。
- 每笔显示：商家／说明、类别、金额、记录渠道小图标；收入用不同颜色与支出区分。
- **待补全：** 金额位置显示“—”，旁边提示“无法识别金额，需要用户自行查看”。点进去可直接补填金额。
- **待核对重复：** 显示“可能重复”标签。点进去可以选择“两笔都保留”或“删除这一笔”。应用不会自动合并。
- 顶部提示条：“本月有 N 笔待补全、M 笔待核对”，点击只显示这些记录。没有需要处理的记录时不显示。
- 空状态：当月没有账目时显示“本月还没有记录”和“记一笔”按钮。

## 4. 记一笔／编辑

- 先选“支出／收入”，再填金额、类别、日期（默认现在）、商家／说明、备注。
- 选择收入类别后出现“具体来源”。可从已有来源中点选，也可当场新增，例如新增“兼职 C”。来源名称一致，统计就不会被拆散。
- 金额必须大于 0；手动记录时金额必填。只有自动记录可能出现空金额。
- 支出可勾选“这是退款”：保存为负支出，可选择关联的原交易，类别默认与原交易相同。
- 修改自动记录时，记录渠道保持不变，便于日后追查。
- 补填金额后状态从“待补全”变为“正常”，相关月报立即更新。
- 删除前需要确认。删除的账目进入设置页的“最近删除”，30 天内可恢复，之后自动清除；删除的账目不计入任何统计（2026-10-12 已确认）。
- 被删除的自动记录不会因同一封邮件或同一次触发再次处理而重新出现。

## 5. 月报

月报页顶部选择月份。**进入新月份后，默认显示上个月**，并标注“生成于 X 月 1 日，最后更新于 …”。也可以切换到本月查看进行中的数字。

如果该月有待补全记录，月报顶部提示：“有 N 笔金额未补全，以下统计不完整”，点击可前往补全。

### 5.1 支出报表

- 支出总额。
- 各类别：金额、占总支出百分比，用横向柱状图从大到小排列。
- 百分比保留一位小数；由于四舍五入，合计可能显示为 99.9% 或 100.1%。
- 待补全的交易不计入金额，也不计入百分比的分母。
- 退款（负支出）从对应类别和总支出中扣除。
- 自动记下、仍是“未分类”的 Apple Pay 支出单独显示为一行“Apple Pay”；手动改过类别的按所选类别统计；手动记的“未分类”仍算“未分类”（2026-10-26，消费习惯页同样处理）。总额不变。

### 5.2 收入报表

- 收入总额，以及各收入类别的金额和占比。
- 点开一个类别（例如“兼职”），显示其下各具体来源的金额和占总收入的百分比。
- 类别与具体来源分层显示，总额只按类别加一次，不会重复相加。
- 没有填写具体来源的收入，显示为“未指定来源”。

### 5.3 收支对比

- 同一个月的收入和支出，用同一刻度的两根柱子比较。
- 下方显示差额：收入 − 支出。为负时用醒目颜色标出。
- 只比较所选月份，第一版不做跨月趋势。

## 6. 自动记账行为

### 6.1 两个入口

| 入口 | 触发 | 写入的账目 |
| --- | --- | --- |
| 实体店 Apple Pay | iPhone 钱包付款后的自动化 | 支出；金额、商家、时间以实际获取为准 |
| 邮件账单（DoorDash、Uber Eats、Uber 打车及用户加入名单的商家） | Gmail 收到邮件后，正常约 15 分钟内 | 名单内商家按规则自动记支出；未列入名单但像收据的邮件进入“待查看邮件”，不自动入账 |

- **默认类别：** DoorDash、Uber Eats 为“餐饮”；Uber 打车为“交通”；用户加入名单的商家使用加入时选择的类别。Apple Pay 记录为“未分类”。不按商家名猜测细分类别。“未分类”只是普通类别，正常计入支出，不提醒、不要求补选；你想改时可以随时修改。
- 任一字段识别失败时仍写入账目，缺金额则标为待补全；不会因识别失败而丢弃交易。

**邮件范围（2026-10-22 更新）：** 内置支持 DoorDash 外卖、Uber Eats 外卖和 Uber 打车；熊猫外卖已移除。用户可将其他发件商家加入自动记账名单。名单外看起来像收据的邮件只进入“待查看邮件”，不会自动入账。各类自动记录均须用真实邮件验证；退款与修订规则（6.3）同样适用。

**待查看邮件：** 显示发件网域、日期和识别到的金额；不保存完整发件地址、主题、正文或片段。用户可以“记这一笔”、将商家加入自动记账名单并选择类别、静音该商家，或只标记这一封已查看。静音只影响邮件提醒，不会自动创建账目。

### 6.2 去重

- 同一封邮件或同一个订单号重复处理时，不新增账目。
- 不同入口疑似同一笔消费（金额相同、商家相近、时间接近）时，两笔都保留并标“待核对重复”，由你决定。
- 不确定是否重复时一律提示核对，不擅自合并或删除。

### 6.3 退款与金额修订（2026-10-12 已确认：方案 A）

- **退款：** 收到同一订单的退款邮件时，新增一笔负支出，关联原订单，类别与原交易相同。原账目保持不变，可以看到“花了多少、退了多少”。
- 退款按退款日期归属月份。月报中该类别和总支出自动扣除退款。
- 退款金额无法识别时，这笔退款标为待补全。
- **其他金额修订**（例如事后修改小费）：不新增账目，把原账目标为“待核对金额”，提醒你查看。
- 同一封退款邮件重复处理时，不重复新增。

### 6.4 状态可见

设置页显示每个自动入口的状态：最后一次成功记账时间，最近一次错误（例如邮箱授权失效、免费额度用完）。出现错误时，账目页顶部也显示提醒。服务暂停不会转为收费，而是提示受影响的功能。

## 6A. 预算与小助手（2026-10-13 新增，逐项经用户确认）

### 6A.1 预算

- 在设置页填写**每月总预算**；可选为部分支出类别单独设预算。未设预算的类别只计入总预算。
- “未分类”不能单独设预算，只计入总预算。
- 预算每月自动沿用，不用每月重填；随时可以修改，修改从当月起生效。
- 预算只针对支出；收入不设预算。退款（负支出）冲减对应预算的已用金额；待补全的金额未知，不计入已用金额，但会提示“有 N 笔未补全，预算统计不完整”。

### 6A.2 小助手的位置与形式

- 每个页面的**左上角**都有一个小图标。有新提醒时显示小红点，点开看过后消失。
- 点开后是**对话窗口**：小助手把提醒、夸奖一条条发给你；下方是预设的问题按钮，点一下小助手就回答。
- 第一版小助手**按规则生成回答**，不调用外部 AI 服务，账目不外传，也不能自由打字提问。结构上为以后增加按钮、提醒类型，以及升级为真正的 AI 对话（增加输入框）预留位置；接入外部 AI 需另行批准。
- 只在应用内说话，不主动推送通知。

### 6A.3 提醒与夸奖（建议的默认规则）

| 类型 | 何时出现 | 示例 |
| --- | --- | --- |
| 接近预算 | 总预算或某类别预算已用达到 80%（比例可在设置中调整） | “餐饮已用 85%，本月还剩 9 天，注意一下哦” |
| 超出预算 | 已用超过 100% | “购物本月已超出预算 30 美元” |
| 进度良好 | 月中后，已用比例明显低于本月时间进度 | “本月过去一半，总预算才用了 35%，保持得很好！” |
| 上月表扬 | 新月份开始时，上月总支出未超预算 | “上个月比预算少花了 120 美元，做得好！” |
| 待处理 | 有待补全或待核对的账目 | “还有 2 笔金额没补全，补上后预算统计会更准” |

同一条提醒不重复刷屏：同一预算的同一类提醒，状态变化后才再次出现。

### 6A.4 预设问题按钮（第一版）

1. **本月到今天的收支**（用户指定）：在月内任意一天，显示本月 1 日至今天（费城时间）的支出总额、收入总额、差额，以及支出、收入各类别的金额；注明未补全笔数。
2. **这个月还能花多少？** 总预算与各类别预算的剩余金额。
3. **哪个类别花得最多？**
4. **跟上个月同期比怎么样？** 本月到今天与上月同一天数的支出对比。
5. **还有几笔没补全／待核对？** 点击可前往处理。

### 6A.5 月报中的预算小结

月报页增加“本月预算小结”：总预算与各类别预算的已用、剩余或超出金额，以及小助手的一句总结。

### 6A.6 生成个人收支交易表格（2026-10-22）

- 小猫助手提供“生成交易表格”入口，使用者选择开始与结束日期后直接生成报表，不显示报表预览页，也不要求输入交易文字。
- 报表仅包含所选范围内的已有交易，按月份分组，列出日期、交易说明、分类、收入、支出、余额和金额完整状态。期初余额承接开始日期之前的所有未删除账目；账户最初余额为 $0.00，余额跨月连续累计。若范围内或期初历史有待补全金额，必须明确标记并说明余额不完整。
- 每个涉及月份如有预算，只显示总预算对比，并用该自然月的整月支出实际数明确标注，避免把部分日期误当作整月实际数；不列出类别预算行。应用其他预算页面及月报的类别预算逻辑不变。
- 手动交易的分类栏显示用户所选类别；自动 Apple Pay 交易显示“Apple Pay”，所有 Gmail 来源的自动记账交易（包括 Uber 行程）显示“Online Order”。自动来源名称只用于显示，不覆盖交易存储的消费类别。
- 余额连续累计；类别缺失不影响余额完整性。期初或范围内有缺失金额时，标注金额待补全及相关余额不完整。
- 每次生成创建一个只包含该报表的独立 Google Sheets 文件，使用者可直接在 Google Sheets 打开，或下载同一报表的 Excel `.xlsx` 文件。独立文件确保 Excel 导出不会包含原账本中的其他工作表。
- 生成只读取账本、不写入或修改任何交易。只使用已配置的 Google Sheets 能力，不调用外部 AI 或新增付费 AI 服务；生成失败时清楚显示错误，保留日期选择以便重试。

## 6B. 界面语言（2026-10-26 新增，经用户确认）

- “我的”页新增一行“语言 / Language”，可选“中文”或“English”，默认中文。选择记在本设备的浏览器里（与音效开关相同）；换设备或浏览器需重新选择。不需要重新运行 `setupLedger`。
- 切换后立即生效，不需要重新登录。会切换的内容：所有页面文字、按钮、提示与错误信息、日期和月份写法、内置默认类别名称（如“餐饮 ↔ Dining”）、小猫助手的问题按钮与回答。生成交易表格时，表头与说明使用生成那一刻的界面语言。
- 不切换的内容：用户自己输入的自建类别名、兼职来源名、商家名与备注；以前生成的交易表格文件（快照）；脚本编辑器日志与 `docs/` 设置指南（保持中文）。已保存的小猫助手消息尽量随语言显示，个别无法识别的旧消息保留原文。
- 「账本」表格中保存的内容（类别名等）不因切换而改变；切换只影响显示。

## 7. 验收场景

以下数字均为测试示例，不是真实账目。

| 场景 | 操作 | 预期结果 |
| --- | --- | --- |
| 支出构成 | 同月录入餐饮 120、购物 80 | 总支出 200；餐饮 60.0%、购物 40.0% |
| 收入来源 | 同月录入兼职 A 600、兼职 B 400（两笔都选“兼职”类别） | 收入总额 1,000；“兼职”100%；展开后 A 60.0%、B 40.0% |
| 收支对比 | 使用以上账目 | 收入 1,000、支出 200、差额 800；柱子与数字一致 |
| 待补全 | 加入一笔无金额的支出 | 列表显示“—”和提醒；首页与月报提示 1 笔未补全；合计仍为 200 |
| 补填 | 补填该笔为 50 | 提示消失；总支出 250，占比随之更新 |
| 月份归属 | 费城时间 1 月 31 日 23:30 的交易 | 归入 1 月，不受手机所在时区影响 |
| 重复收据 | 同一封 DoorDash 收据处理两次 | 只有一笔账目 |
| 删除与恢复 | 删除一笔 DoorDash 自动记录，再处理同一封收据；之后从“最近删除”恢复 | 删除后不重新出现、不计入统计；恢复后回到原月份并重新计入 |
| 退款 | 1 月餐饮 120，2 月收到其中 20 的退款 | 原账目不变；2 月新增 −20 关联原订单；1 月餐饮 120，2 月餐饮扣减 20 |
| 真实邮件账单 | DoorDash、Uber Eats 外卖及 Uber 打车的真实 Gmail 收据 | 分别验证类别、商家和实付总额；无法识别金额时显示待补全；未列入名单的邮件不得自动入账 |
| 待查看邮件 | 一封名单外、像收据的邮件 | 显示网域、日期和金额；四种操作按选择处理；主题、正文和完整发件地址不保存 |
| 真实 Apple Pay | 一次正常的实体店付款 | 账目金额、商家与付款凭据一致；手动点运行不算通过 |
| 保存 | 关闭后在手机上重新登录 | 所有账目仍在 |
| 预算提醒 | 总预算 1,000、餐饮预算 200；餐饮已记 170 | 小助手图标出现红点；对话中出现“餐饮已用 85%”；点开后红点消失 |
| 预算沿用 | 1 月设定预算，进入 2 月 | 2 月沿用相同预算，无需重填；2 月中修改后，1 月数字不变 |
| 本月到今天 | 某月 1–15 日支出 300、收入 800，16 日后另有记录 | 15 日点“本月到今天的收支”：支出 300、收入 800、差额 500，并列出各类别 |
| 未分类预算 | 在设置中尝试给“未分类”设预算 | 不可单独设置；未分类支出计入总预算 |
| 界面语言 | 在“我的”选 English，依次打开各页面和小猫助手；再切回中文 | 英文模式下各页面内置文字均为英文、默认类别显示英文名、自建类别和备注保持原样；切回中文后恢复中文；重新打开网页仍保持上次的选择 |

## 8. 需要你决定的问题
